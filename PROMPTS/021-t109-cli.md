## What this project is

The product (root `idea.md`) is an open-source fluid-dynamics engine that lets anyone drop in a
shape, set a few physical numbers, and watch the flow — without learning CFD first. Its thesis:
*"The gap is not the solver. The gap is everything around the solver."*

pure NumPy, spec `DOCS/IDEA2.md`, closed at M4 with all four validation rungs green. **Phase 1 is
live**: the product layer above the solver — a `flow/` package plus a CLI, on a Warp GPU backend.
Spec `DOCS/IDEA3.md`, plan `DOCS/PLAN2.md`, backlog `DOCS/TASKS2.md`, live status `DOCS/STATE2.md`.

### Constraints that bite on this task

- **Constraint 13 — no lattice quantity in any public `flow/` signature.** This now has *two*
  scanners and both auto-parametrise over new modules, so `flow/cli.py` is covered the moment it
  exists: `tests/test_flow_package.py` scans parameter **names** against `LATTICE_NAMES`, and
  `tests/test_case.py::test_no_public_flow_signature_mentions_a_lattice_quantity_anywhere` scans
  **annotations and defaults** too. A `--resolution` flag in cells would be the violation to avoid;
  the user-facing knob for resolution is `--quality` (**D-068**).
- **Constraint 8 / D-039 — the mode is not composable, the sinks are.** `drop = not (record or
  headless)`; any sink that writes a file takes `drop=False`. `Case.run()` already implements this
  and `tests/test_case.py` asserts all eight combinations — the CLI should *pass the flags through*,
  not re-derive the rule.
- **Constraint 10 — one `render()`, three sinks, and `flow/` colours nothing.**
  `tests/test_report.py` asserts that the only name any `flow` module imports from `lbm.render` is
  `render` (plus `LiveSink`). A CLI that builds a colormap for a progress bar breaks that test.
- **Constraint 16 — no silent substitution.** If the CLI offers to run the nearest case (via
  `Case.nearest()`), the resulting `Result` carries `substituted=True` and the banner, the dict and
  the MP4's metadata all say so. Do not add a flag that runs a substitute *quietly*.
- **Constraint 5 — the ladder stays a gate.** T109 adds no rung, but all four Phase 0 rungs plus A,
  C and D must still be green when you finish.
- **`DOCS/IDEA3.md` § Scope — no UI.** A prettier terminal output is fine; a TUI framework is not.

**Decisions that constrain this session:**

- **D-067** — a refused `Case` is **built, not raised**: `case.runnable` is `False`, `case.refusal`
  holds it, `case.explain()` prints it, and `case.run()` raises. This is what lets the CLI print an
  explanation and exit 2 without exception plumbing — use that shape rather than wrapping `run()` in
  a `try`.
- **D-068** — a geometry fix arrives as a **quality level**, never as a cell count. `case.nearest()`
  applies the tool's own top suggestion or the picture's fix and returns a `Case` marked
  `substituted=True`.
- **D-038** — the CLI's own historical acceptance command (`--fluid air --velocity 20 --length 1.5`)
  is **refused**, and that refusal is correct and stays. `--help` says so in plain words.
- **D-039 / D-024** — two run modes, and any file-writing sink picks `drop=False`.
- **D-071** — `Case.run(keep_frames=True)` keeps frames in memory under a 512 MB budget and reports
  the shortfall. A CLI that writes with `--out` should pass `keep_frames=False`: the frames are
  already going to a file, and keeping 2.5 GB of them as well is the default nobody chose.
- **D-044** — Phase 1's deliverable is a library plus a CLI. No UI.
